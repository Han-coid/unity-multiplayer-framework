# 中文界面与字体

从 0.3.1 开始，连接、大厅、角色操作、网络诊断和弱网测试面板默认显示简体中文。普通 Windows 示例与大厅示例都已重新构建，运行中的旧程序需要关闭后重新打开才能更新。

## 界面文字

| 原按钮 | 当前按钮 |
| --- | --- |
| LAN host / Join IP | 创建局域网主机 / 通过 IP 加入 |
| Create Relay room / Join Relay code | 创建中继房间 / 通过房间码加入 |
| Ready / Cancel ready | 准备 / 取消准备 |
| Start game | 开始游戏 |
| Return everyone to lobby | 全员返回大厅 |
| Kick / Disconnect | 移出 / 断开连接 |
| Show network diagnostics | 显示网络诊断 |

状态、阶段、布尔值和常见拒绝原因也在显示层转换为中文，例如“等待准备”“游戏进行中”“房间人数已满”。错误提示保留原始错误码，便于排查。网络协议、RPC 名称、日志标记、JSON 字段和命令行参数保持原有格式；未知第三方异常保留原文，防止丢失关键信息。玩家自己填写的昵称按原样显示。

## 字体选择

`Han.Multiplayer.UI` 是独立的轻量显示程序集。`ChineseGui.Use()` 为一次 IMGUI 绘制临时应用中文字体和深色不透明皮肤，结束后恢复原皮肤，不修改其他项目 UI。

字体按以下顺序选择：

1. 项目中 `Resources/HanMultiplayer/ChineseFont` 对应的 Font 资源。
2. 系统已安装的中文字体。Windows 优先微软雅黑；macOS/Linux 尝试对应的中文字体。
3. 没有可用中文字体时保留默认字体并打印提示。

本机已通过实际窗口确认微软雅黑可以显示中文。程序使用系统字体 API，没有把 Windows 字体文件复制或打包进项目。

面向 WebGL、手机或没有中文系统字体的设备发布时，应自行准备许可允许分发的中文字体，将其放在例如 `Assets/Resources/HanMultiplayer/ChineseFont.ttf`，确认 Unity 将它导入为动态 Font。不要只凭 Windows 显示正常就推断其他平台不缺字。

自己的脚本使用 asmdef 时，引用 `Han.Multiplayer.UI`；在 `OnGUI` 中用 `using (ChineseGui.Use())` 包围绘制代码即可共用字体。它不负责翻译玩家昵称或任意第三方 SDK 的全部错误文本。

## 更新与运行

- 普通示例：`Builds/Windows/MultiplayerDemo.exe`。
- 大厅示例：`Builds/LobbyWindows/LobbyDemo.exe`。
- 双窗口手动验收：项目根目录运行 `scripts/Start-LobbyAcceptance.ps1`。
- 源码重新构建：Unity 菜单仍使用原有英文工具名称，方便对应脚本和教程。

0.3.1 的历史改动仅涉及文字、字体和皮肤；当前 0.8.0 已另行加入时序优化、预测和跳跃。操作入口以对应功能教程为准。

## 中文显示或键盘操作异常时

1. 先确认运行的是重新构建后的程序；源码改了但旧 exe 没变时，不会出现新按钮。Unity 工具菜单仍为英文，这是正常情况。
2. 方框/缺字：检查 Resources/HanMultiplayer/ChineseFont 是否是可加载的 Font 资源，路径大小写是否一致；只有 TextMeshPro 的 TMP_FontAsset 不能直接作为本 IMGUI Font 使用。
3. 只在某一平台缺字：把可合法分发的中文字体作为项目资源打包，在目标设备检查；不要依赖开发机安装的字体。
4. 键盘不动但屏幕按钮可用：点击游戏空白处，把焦点移出文本框；检查 Input Manager / 新 Input System 接入。中文字体不会替你接入输入系统。
5. 面板遮挡角色：拖动诊断面板标题栏，或收起诊断；收起不会停止弱网注入，需要另点“恢复正常网络”。

已知提示差异：诊断复选框的“额外回执最多 10 次/秒”只描述 Legacy 测量路径；预测的必要权威同步行为见 [时序教程](同步时序与延迟优化.md)。
