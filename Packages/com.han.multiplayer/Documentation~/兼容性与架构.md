# 兼容性与架构

当前示例为 0.8.0、协议 6，需重建两端。新增可选 [跳跃、重力与地面检测](跳跃重力与地面检测.md)，包括垂直状态校正与空中恢复；下文带旧版本号的段落保留其历史说明。

## “兼容”分成三个问题

1. **Unity 版本**：本项目以 Unity `6000.3.26f1` 为验证基准。包元数据最低版本为 `6000.0`，并不表示所有 Unity 6 小版本都经过测试。Unity 2022.3 不在本版支持基线内，需要单独选依赖并做适配测试，不能直接承诺兼容。
2. **平台**：核心采用 Unity C# / NGO / UTP API，没有 Windows 专用运行时代码。Windows、macOS、Linux、Android、iOS 和 WebGL 仍要分别构建与实机测试。
3. **跨平台互通**：客户端必须使用相同的游戏 ID、协议版本、网络预制体和兼容的 SDK / 游戏数据。只有“都能编译”不足以证明互通。

| 目标 | 设计接入方式 | 本版验证范围 / 限制 |
| --- | --- | --- |
| Windows PC | LAN / 直连服务器 / Relay | 使用本机 Unity 与 Windows 构建进行验证，详见验证记录 |
| macOS / Linux 客户端 | 同上 | 未构建、未实机测试 |
| Android / iOS | LAN / 直连服务器 / Relay | 未实机测试；需触控 UI、网络权限和后台恢复策略 |
| WebGL | Relay WSS | UDP 直连入口明确拒绝；未做浏览器构建与联调 |
| Linux Dedicated Server | 局域网 / 公网 IP + UDP 端口 | 已完成 Linux x86_64 / Mono 专用服务端构建；尚未部署或运行验证 |
| 主机平台 | 平台许可、网络 SDK 与账号适配 | 不在本版验证或交付范围 |

浏览器参与的房间统一选择 **WSS**：桌面 / 手机主机也勾选 WSS，以保证示例的协议配置一致。WebGL 构建会自动使用 WSS。不要把浏览器“可选协议”误解为能直接打开 UDP socket。

手机进入后台可能暂停主循环并断开连接。安装并启用 `RecoveryService` 后，框架会在客户端进程内保留恢复凭证，并在重新获得执行机会时按恢复预算尝试重连；这条代码路径尚未在 Android/iOS 后台切换中实测。凭证不写入磁盘，系统杀掉客户端进程后不能继续恢复；后台停留超过服务器席位保留期也可能恢复失败。iOS 本地网络权限、Android 网络权限以及目标系统防火墙需要在对应构建中确认。默认保留期 30 秒、重试预算 45 秒，二者不是同一个计时器，见 [恢复模块](断线重连与状态恢复.md)。

项目 `Packages/manifest.json` 固定主要 SDK，`packages-lock.json` 记录完整解析结果。复用到其他项目时，要检查目标项目是否已有不同版本的 SDK，并重新运行测试。不要同时安装旧独立 Relay SDK 和新的 Multiplayer Services 包。

Linux 构建模块已安装。已只读确认目标机器为 Ubuntu 26.04.1 / x86_64；这个系统版本仍需实机运行确认。Linux 部署包和启动方式见 [Linux 服务器部署](Linux服务器部署.md)，当前按用户要求仅保留本地产物。

## 职责与权威

- 连接管理：`MultiplayerSession` 独占该 `NetworkManager` 的启动、停止和 ConnectionApproval 回调。游戏 UI 不要再直接调用 `NetworkManager.StartHost/StartClient/Shutdown`。
- 云服务：`UnityRelayProvider` 只返回连接数据。等待云服务时取消操作，迟到结果不会重新启动 Transport。底层 UGS HTTP 请求本身无法取消，未绑定分配由服务端超时回收。
- 角色：NGO 创建玩家对象；客户端发送移动意图，服务器限幅后执行，NetworkTransform 将位置传回客户端。
- 持久状态：用服务器写入的 `NetworkVariable`，让后加入者也能读取当前状态。
- 瞬时操作：使用 RPC，并检查发送者权限和游戏条件；不能把客户端报告的位置、伤害或货币值直接当成可信结果。

`ApplicationId` 和 `ProtocolVersion` 是兼容检查，**不是登录或身份认证**。客户端可以伪造这些值。匿名 Unity Authentication 用于访问 Relay，也不等同于你的游戏服务端已经校验玩家账号。公开运营时应另加后端签发并验证的短期凭证。

直连传输仍使用普通 UDP，未自动配置加密；0.6.0 可选账号模块提供应用层准入和请求授权，但不会替换传输层安全。公网正式服务应配置受保护的游戏传输和真正的账号后端。Relay 默认 DTLS / WSS。任何可联网游戏都不能承诺“零延迟”：跨地域物理距离、丢包和主机上行带宽会影响体验。

默认面向 2–8 人的小规模合作游戏。参数允许 2–128 人，只是输入校验范围，不代表完成了 128 人压力测试；实际容量取决于玩法、同步频率、消息量和服务器资源。

## 推荐的扩展顺序

1. 用当前示例熟悉 Host、Client、Server、NetworkObject、NetworkVariable 和 RPC。
2. 接入自己的角色和一个可验证的交互，例如拾取或合作开门。
3. 接入 Unity 云项目并完成两地实机 Relay 测试。
4. 为目标平台添加输入适配和实际打包测试。
5. 按玩法选择已经提供的大厅、独立服务器、恢复和预测模块；匹配、主机迁移、复杂角色控制和 FPS 命中回溯仍需扩展。大规模 MMO / 高对抗 FPS 需要另外设计同步规模与验证方案。


## 可选恢复模块（0.5.0）

`Han.Multiplayer.Recovery` 独立于 FPS、大厅和诊断模块。核心通过 `ISessionContinuity` 连接，大厅通过核心契约保留离线席位；自己的项目只安装需要的组件。恢复当前服务器进程内的逻辑身份与玩家快照，不涵盖进程重启、主机迁移或账号后端。详见 [断线重连与状态恢复](断线重连与状态恢复.md)。


## 追加：账号准入与请求校验（0.6.0）

当前示例协议已升为 6，需重新构建双方。可选账号模块提供凭证供应器、服务器验证器和 HTTPS 后端适配，并与恢复账号绑定；默认 LAN 仍可不启用账号。统一请求校验已接入示例业务入口。详见 [账号准入与请求校验](账号准入与请求校验.md)。开发验证器只模拟账号，不能替代真实登录后端，且在正式构建强制禁用。

## 追加：基础移动预测（0.7.0）

可选水平移动预测已实现，示例默认启用。接入、适用边界和验收见 [基础移动预测与服务器校正](基础移动预测与服务器校正.md)。当前示例协议为 6，所有参与者需重新构建。
