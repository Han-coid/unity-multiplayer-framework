# 基础移动预测与服务器校正（0.8.0）

这是独立、可选的 `Han.Multiplayer.Prediction` 玩法模块，不要求所有联机项目经过 FPS 层。它实现固定 Tick 的基础水平移动、本地预测、服务器确认、未确认输入重放和展示平滑。服务器始终决定真实位置，客户端不上传位置或时间步长。

0.8.0 新增可选 [跳跃、重力与地面检测](跳跃重力与地面检测.md)，示例默认开启。使用轴对齐箱形角色和显式静态箱体；自己项目关闭 EnableVertical 时保留水平 X/Z 运动。不是通用物理回滚：不包含坡面、动态 Rigidbody、玩家之间碰撞、移动平台或射击命中回溯。示例外观是胶囊，但运动碰撞模型是其外接箱体。

## 1. 两个窗口体验

基础与大厅 Windows 程序已重新构建。项目目录 PowerShell 运行：

```powershell
.\scripts\Start-LobbyAcceptance.ps1
# 也可同时验收已有账号准入
.\scripts\Start-LobbyAcceptance.ps1 -DevelopmentAccounts
# 关闭两个窗口后，启动关闭本地预测的对照组（服务器模拟相同）
.\scripts\Start-LobbyAcceptance.ps1 -PredictionMode Off
```

1. 两端准备后由房主开始游戏，左侧显示「本地预测 + 服务器校正」。
2. 重点操作远端客户端；Host 自己在本机运行权威模拟，不经过远端链路，也不会生成本地预测替身。
3. 在客户端诊断面板选择「中度」或「严重」弱网，移动后停止、反向，观察自己的角色可以立即响应，对方角色仍按服务器状态插值。
4. 场地中央有一面演示墙。向墙移动应停止，斜向移动会沿墙滑动；不要把这面演示墙等同于任意 Unity Collider 的自动适配。
5. 左侧显示待确认输入、校正次数、最近校正误差、校正时重放的输入数，以及是否等待重新定基。正常网络中校正次数很少是正常现象。
6. 停止并关闭两窗口，再用关闭预测的客户端对比。若通过界面切换，请先断开，再选择「关闭预测」后加入；服务器可以继续保持开启预测。On/Off 使用相同的输入协议和服务器模拟。
7. 测试「模拟连接中断」及恢复，角色应恢复服务器保留的位置，不继续执行旧网络对象的输入。

命令行：`--net-prediction on` 开启本地预测，`off` 只关闭本地展示预测，`legacy` 使用原来的移动协议。Legacy 必须两端一致；旧的「原版 30 Hz」界面选择会切回 Legacy。预测模式用 NGO 网络 Tick，不走项目 FixedUpdate，也不修改全局 Fixed Timestep。

## 2. 数据流与权威边界

```text
本地采样 → 量化输入 → 固定 Tick 预测 → 本地可见模型
                      │
                 最近输入窗口补发
                      ↓
服务器权限/阶段/频率检查 → 顺序队列 → 每 Tick 最多执行一条
                      │
    确认序号 + 位置/垂直速度/落地状态 + 输入代次
                      ↓
客户端从完整权威状态重放尚未确认输入 → 平滑可见模型
```

每条输入以两个字节保存 X/Z，服务器重新限制为单位向量；另用一个 32 位位图保存窗口内的跳跃脉冲。一个包固定包含最多 32 条连续序号的输入槽位，不按客户端指定长度分配数组。窗口重叠会去重，过远的未来输入被拒绝；服务器不会因某客户端一次多发几包就多模拟几步。

`NetworkTransform` 根对象始终是服务器权威状态，远端玩家继续使用其插值。本地预测只改变显示位置。这样不会让客户端强行写根 Transform，也避免每帧被 NetworkTransform 覆盖。角色根位置与本地看到的位置可能不同，自己的相机、动画和特效应跟随展示位置，不能直接假定根对象就是预测视图。

## 3. 在自己的项目安装

### 3.1 网络根对象与玩家

1. NetworkManager / MultiplayerSession 同一对象添加 `MovementPredictionSession`。
2. 设置核心 TickRate，推荐先用 60；两端 Tick 配置必须一致。
3. 在注册的玩家预制体添加 `PredictedMovement`，同时保留 `NetworkObject` 和服务器权威 `NetworkTransform`。根对象不能再由另一套移动脚本或 Rigidbody 积分竞争写入。
4. 配置相同的 MovementSettings：Speed、HalfWidth、Minimum/Maximum 和 Obstacles。单位为世界单位，障碍 Center/HalfSize 为 X/Z 矩形；不是 Transform 的自动缩放值。
5. 出生和恢复位置必须在边界内且不与静态墙重叠。运行中不应热改这份几何；会话开始时使用副本。

6. 在网络根对象上添加 `ServerRequestGate`（位于 `Han.Multiplayer.Security`），或提供自己的 `IServerRequestValidator`。不要求启用账号服务即可使用 Gate。自带 `DemoLauncher` 会安装它，但只复制前面的预测组件到新项目不会自动安装。
7. 玩家预制体根节点保持单位缩放；创建名为 `VisualRoot` 的空子节点，局部位置/旋转清零、缩放为 1，把显示模型放在其下面。将 `VisualRoot` 拖入下面适配脚本的 `Visual` 字段；模型自身需要的高度偏移放在更下一级，不放在 `VisualRoot` 上。
8. 在服务器的 `OnNetworkSpawn` 设置合法出生点。使用恢复时，把 `RecoverablePlayer` 排在 `PredictedMovement` 前面（Inspector 组件菜单 Move Up/Down）；保证恢复位置先于预测的 PostSpawn 初始化应用。所有参与者使用相同组件及顺序并重新构建。

典型玩家层级如下；不是要求同时保留 DemoPlayer 和自己的移动脚本：

```text
Player（NetworkObject、服务器权威 NetworkTransform、业务出生/恢复适配）
  ├─ RecoverablePlayer（需要恢复时，排在 PredictedMovement 前）
  ├─ PredictedMovement、BasicPredictionBridge（实际为根对象上的组件）
  └─ VisualRoot（空 Transform，赋给 Visual）
       └─ Model（MeshRenderer 或自己的带动画模型，可有局部偏移）
```

没有 Gate/替代验证器时，核心仅保留连接、所有权、载荷和阶段等基本检查；**不会执行统一的请求频率预算**。预测模块仍有输入窗口去重和每 Tick 一步的限制，但它们不等于请求限流。账号启用时，还需验证器签发 `play` 权限。Gate 的安装与自定义入口见 [请求校验教程第 6 节](账号准入与请求校验.md#6-统一请求校验)。

运动配置指纹包含 Tick、水平速度、角色宽高、垂直开关、重力/跳跃/下落速度、地面高度、水平边界、静态箱体及其顺序。客户端与服务器不一致时停止移动，示例 UI 显示错误；自己的 UI 应读取 `ConfigurationMismatch` 提示用户。指纹是配置一致性检查，不是加密签名；真正的权威检查仍由服务器执行。

自己的 asmdef 引用 `Han.Multiplayer`、`Han.Multiplayer.Prediction` 和 `Unity.Netcode.Runtime`。此程序集不引用 Demo、FPS、账号、恢复、大厅或诊断程序集。

### 3.2 输入、玩法许可与展示适配

将输入交给 `PredictedMovement.SetInput(input, MovementClock.Now)`。组件会在固定 Tick 取最近输入，客户端不提供 dt。下面是可直接调整的适配骨架，保存为 `BasicPredictionBridge.cs`：

```csharp
using Han.Multiplayer.Prediction;
using Unity.Netcode;
using UnityEngine;

[RequireComponent(typeof(PredictedMovement))]
public sealed class BasicPredictionBridge : NetworkBehaviour,
    IMovementAuthorityPolicy, IMovementPredictionObserver
{
    public Transform Visual; // 根对象下只负责显示的模型，不挂驱动角色的物理控制器。
    public readonly NetworkVariable<bool> MovementAllowed = new NetworkVariable<bool>(true);
    PredictedMovement movement;

    public bool CanSimulateMovement => MovementAllowed.Value;

    public override void OnNetworkSpawn()
    {
        movement = GetComponent<PredictedMovement>();
    }

    void Update()
    {
        if (!IsSpawned || !IsOwner) return;
        Vector2 input = Vector2.zero;
#if ENABLE_LEGACY_INPUT_MANAGER
        // 输入框获得焦点或窗口在后台时，不读取键盘移动与跳跃。
        if (Application.isFocused && GUIUtility.keyboardControl == 0)
        {
            input = new Vector2(Input.GetAxisRaw("Horizontal"), Input.GetAxisRaw("Vertical"));
            if (MovementAllowed.Value && Input.GetKeyDown(KeyCode.Space)) movement.RequestJump();
        }
#endif
        // 使用新 Input System 或触屏时，将上面的采样替换为自己的输入来源。
        movement.SetInput(MovementAllowed.Value ? input : Vector2.zero, MovementClock.Now);
    }

    public void OnMovementPresentation(Vector3 position, bool locallyPredicted)
    {
        if (Visual == null) return;
        if (locallyPredicted) Visual.position = position;
        else Visual.localPosition = Vector3.zero;
    }

    // 可选诊断埋点：不需要诊断时保留空实现。
    public void OnMovementInputSent(uint sequence, double sampledAt, double sentAt) { }
    public void OnMovementConfirmed(uint sequence, double now, float queueMs, float workMs, float serverHz) { }
    public void OnMovementEpochReset() { }
}
```

`Visual` 应为根对象下的显示子节点；若预制体本身就在根上渲染，应改为子节点或采用自己的展示适配器，避免同时出现两个模型。示例 DemoPlayer 会为本地非 Host 玩家创建显示替身，并隐藏本地根网格；它只适配示例的 MeshFilter/MeshRenderer，不是通用的 SkinnedMeshRenderer 克隆器。

将脚本挂到玩家根对象，注册并使用这个预制体后再启动连接。这个骨架负责输入、许可和展示，不负责出生位置、相机、账号登录或恢复快照。只安装该骨架时不会自动带入示例墙体：需要两端配置相同 Obstacles，并为每个箱体另建可见模型。启用跳跃还需要设置 `EnableVertical=true`，完整参数见 [跳跃接入](跳跃重力与地面检测.md)。

`IMovementAuthorityPolicy` 在服务器和客户端各自读取。真正的游戏阶段/眩晕等许可由服务器维护，不能由客户端自报。示例使用大厅的 Playing 阶段；许可变化会更换输入代次，清除旧排队输入。

### 3.3 服务器校正与传送

```csharp
// 服务器施加位置修正：保留同一输入代次，客户端按确认序号重放后续输入。
movement.CorrectOnServer(validServerPosition);

// 真正传送或重置：清除旧输入、更换代次，并同步 NetworkTransform 传送。
movement.TeleportOnServer(validServerPosition);
```

两者均只允许服务器调用，目标位置必须符合静态运动世界。不要只在外部脚本修改根 Transform；移动组件的权威状态可能在下一 Tick 把它覆盖。恢复组件先恢复服务器根位置，再由预测组件在 PostSpawn 读取并建立新历史。

客户端内部每次从服务器确认位置重新执行未确认输入。小误差在显示层约 80 ms 衰减，大于 2 米的显示误差直接归位；若平滑后的显示点进入墙内，则放弃该显示偏移。不能将“显示平滑”当成服务器放宽碰撞判定。

## 4. 缓冲、丢包与恢复

- 客户端最多保留 256 条输入，发送窗口最多 32 条，服务器最多缓存提前 128 条。
- 输入缺口不会被当成成功执行，重复和旧序号不会重复移动或跳跃。服务器每个 Tick 只推进一次，停止收到可执行输入时水平移动停止，但启用垂直运动时重力仍继续推进。
- 缺口后已有未来输入却等待超过 0.25 秒，或客户端确认进度停滞超过 1.5 秒时，会要求服务器重新定基。严重网络中可能出现回拉/暂停，这比无限保留不可信预测更可控。
- 重新定基会更换输入代次、清空历史与排队输入；旧代次的迟到包不能继续推动角色。客户端本地请求间隔至少 1 秒；服务器统一限流需要第 3.1 节的 Gate/替代验证器，默认重定基规则为 1 次/秒、突发 1 次。
- 断线重连生成新的网络对象，重新读取服务器角色快照并从新历史开始；不恢复旧客户端的未确认指令。

这些默认上限是基础示例的取舍。高 RTT、移动端后台暂停或长时丢包可能触发定基；本模块不承诺任何网络条件下都无回拉。需要更复杂物理或动态障碍时，应替换/扩展两端相同的运动状态与重放算法，并升级自己的协议。

## 5. 指标与自动验收

```powershell
.\scripts\PredictionTest.ps1
.\scripts\PredictionComparisonTest.ps1
# 单独检查
.\scripts\PredictionTest.ps1 -Case Moderate
.\scripts\PredictionComparisonTest.ps1 -Profile Normal
```

PredictionTest 在真实 Host/客户端验证墙体阻挡、沿墙滑动、开发误差注入后的校正与未确认输入重放、服务器校正、传送代次、双向全丢包 3 秒后重新定基，以及配置不一致。为了保证回环网络也有待确认输入，校正重放阶段显式注入 80 ms 上行延迟，再恢复该组原有弱网参数。

PredictionComparison 在相同的 60 Hz 输入协议、服务器模型和静态场景下比较 on/off，依次运行正常、中度和严重弱网，只在客户端注入故障。目标 120 FPS，预热后采集 20 秒；报告仍记录实测 FPS、输入 Hz、确认耗时和静止起步位置响应。

结果在 `TestResults/Prediction/summary.json`、`TestResults/PredictionComparison/summary.json`，日志在对应 Logs 子目录。每组起步样本不多，P95 不能视为长期尾延迟保证。开启预测降低的是本机等待权威位置的显示响应，不会降低 UTP 网络 RTT，也不会让其他玩家的服务器状态提前到达。

起步耗时是输入采样到软件在帧末观察到位置变化至少 0.02 米，不含键盘硬件、GPU、显示器扫描或实际 input-to-photon。局部帧间展示会外推不足一个 Tick 的输入，因此可能同一渲染帧就得到位置响应；不能把很小的测量值称为“网络零延迟”。

旧的 `TimingComparisonTest.ps1` 明确使用 `--net-prediction legacy`，继续比较 0.4.0 的旧时序实现，不把两套移动协议混入同一个时序结论。常规账号、重连、大厅和弱网脚本仍应回归。

## 6. 版本与适用范围

### 常见接入故障

| 现象 | 检查顺序 |
| --- | --- |
| 本地模型和根对象来回争抢位置 | 移除其他写根 Transform 的移动脚本/物理积分；确认只有服务器写根对象、本地只移动 VisualRoot |
| 两个重叠角色 | 检查根 Renderer 是否还显示；自己的适配使用子模型，不同时使用 DemoPlayer 的克隆适配 |
| 显示配置不一致 | 比较两端 Tick、EnableVertical、全部几何与运动参数；确认 exe 已重建，出生点不在障碍内部 |
| 能连接但不能移动 | 确认对象属于本地玩家、大厅已 Playing、策略允许、账号有 play 权限；检查 Gate 拒绝原因 |
| 空中重连后速度归零 | 检查是否保存了服务器垂直速度，以及 RecoverablePlayer 是否早于预测组件完成 PostSpawn |
| 关闭诊断仍有网络流量 | 正常：预测权威状态仍需传输；关闭测量不关闭游戏同步 |
| 严重弱网回拉或等待定基 | 先恢复正常网络，观察能否收敛；不要只扩大历史窗口掩盖不可持续的 RTT/丢包 |

包为 0.8.0，自带示例协议为 **6**，玩家预制体包含 PredictedMovement。请重新构建双方；自己的项目也需要统一网络预制体和兼容版本。On 与 Off 可以混用，Legacy 与命令移动不能混用。垂直运动接入还需保存和恢复速度，详见新增教程。

适用于先验证合作/动作/俯视角等基础水平移动，也可以成为后续 FPS 移动预测的起点。并非确定性全局帧同步，没有回滚整局世界、预测射击或处理任意现成角色控制器。Linux 服务端仅进行本地编译/打包，未上传或运行；移动端、WebGL、真实 Relay 和不同 CPU 的浮点表现仍需实机验收，不能把本机 Windows 测试等同于所有平台验证。

## 7. 移动重放、物理回滚和命中回溯的区别

物理回滚用于修复“本地先计算的碰撞过程与服务器结果不同”。例如客户端预测角色撞到箱子、箱子被推开，但稍后服务器确认的位置表明那次碰撞并未发生；只修正角色位置会让箱子仍留在错误位置。需要恢复同一时刻相关物体的状态，再重算后续输入和物理过程。

| 机制 | 恢复 / 查询什么 | 本项目现状 |
| --- | --- | --- |
| 基础移动预测重放 | 角色位置、垂直速度、落地状态，从服务器确认处重放未确认输入 | 已实现，共享静态箱体运动模型 |
| 动态物理回滚 | 受影响物体的位置、旋转、线速度、角速度及参与碰撞/约束所需的状态，再进行物理模拟 | 未实现；现有预测不能自动回滚 Rigidbody 箱子、车辆或连锁碰撞 |
| 射击命中回溯 | 根据射击时间和允许窗口查询历史命中盒，判定那一刻是否击中 | 未实现；通常不需要把整局物理世界回滚并重放 |

回滚通常发生在客户端预测校正过程中，服务器仍决定有效结果。它减少的是错误预测后的状态分歧，不会缩短网络 RTT，也不保证画面完全没有回拉。需要有界历史、统一模拟时钟和对物理事件的处理；例如重放碰撞时不能重复扣血、播放音效或发放奖励。

Unity Rigidbody/PhysX 模拟不能仅凭保存 Transform 就实现可靠回滚；是否能够重现碰撞结果还取决于相关对象状态、接触/约束、模拟顺序和目标平台。对静态地面、墙体、跳跃、规则化坡面和台阶，可先扩展本项目共享运动模型。只有需要本地预测动态物理交互时，再决定回滚哪些物体以及如何控制重算成本；移动平台也可以先采用服务器驱动的明确轨迹，并不必然要求回滚整个物理世界。
