# 当前项目能力、模块安装与验收清单（0.8.0）

本页是当前版本入口，回答“用哪个模块、要安装什么、怎样知道接入成功”。具体接口和完整代码再进入对应教程。历史版本变更保存在包内 CHANGELOG.md，[验证记录](验证记录.md) 保留各轮测试证据，不能把旧版本成绩当作本次设备测试结果。

## 1. 先确认版本和使用方式

| 项目 | 当前值 | 含义 |
| --- | --- | --- |
| 框架包 | 0.8.0 | `Packages/com.han.multiplayer/package.json` |
| 自带基础 / 大厅示例协议 | 6 | 同版程序、网络预制体和运动配置需配套 |
| 自建 SessionSettings 默认协议 | 1 | 自己游戏独立维护；不要为了连示例只修改数字 |
| 验证基准 | Unity 6000.3.26f1、NGO 2.13.3、UTP 2.7.4 | 声明最低 Unity 6000.0 不代表全部小版本经过测试 |
| Tick | 核心默认 30；Demo 默认响应 60 | 帧率与网络 Tick 是不同指标 |

**完整示例项目**带有 Assets、scripts、Builds 和测试入口；**只导入 UPM 包**可以复用运行时组件和包内文档，但不会自动复制仓库根的脚本或预先构建的 exe。新项目可用 Tools → Han Multiplayer 的菜单生成示例，也可完全使用自己的场景和 UI。代码变化后旧 exe 不会自动更新。

## 2. 按需求安装模块

“网络根”指放置 NetworkManager、UnityTransport、MultiplayerSession 的同一 GameObject。下面是自建项目的安装要求，不能假定 DemoLauncher 在自己的场景中存在。

| 需求 | 网络根 / 玩家上的组件 | 额外前提与成功标志 |
| --- | --- | --- |
| IP 联机 | 网络根：NetworkManager、UnityTransport、MultiplayerSession | 注册 PlayerPrefab 和 NetworkPrefabs；两端生成玩家并同步一次状态，见 [基础接入](接入教程.md) |
| Relay 房间码 | 网络根增加 UnityRelayProvider，并赋给会话 | 配置自己的 Unity 云项目；同机实例分开身份 Profile；跨设备加入码成功，见基础教程第 9 节 |
| 请求校验 | 网络根增加 ServerRequestGate，或自己的 IServerRequestValidator | 内置规则自动注册；自定义规则连接前注册、入口显式调用；匿名 LAN 也可安装，见 [账号与请求](账号准入与请求校验.md) |
| 真实账号准入 | 网络根增加 AccountAdmissionService，配置 CredentialProvider / TokenValidator | Host 需要两者；纯客户端需要凭证供应器；纯服务器需要验证器；自己的后端负责真实登录 |
| 大厅 | 网络根增加 LobbyService，配置 LobbyRoom 网络预制体 | 注册预制体和场景，开启场景管理；从 Entry 进入 Lobby，准备后切 Game，见 [大厅教程](通用大厅接入与验收.md) |
| 自动恢复 | 网络根增加 RecoveryService；玩家根增加 RecoverablePlayer | 自定义业务实现 IPlayerRecoveryState；意外断线后新网络对象恢复原逻辑身份，见 [恢复教程](断线重连与状态恢复.md) |
| 移动预测 | 网络根增加 MovementPredictionSession；玩家根增加 PredictedMovement、服务器权威 NetworkTransform 和自己的输入/展示适配 | 配置一致的静态运动世界；只有服务器写根位置；安装 Gate 才有统一限流，见 [预测教程](基础移动预测与服务器校正.md) |
| 跳跃与重力 | 开启 MovementSettings.EnableVertical，设置角色尺寸和地面/箱体 | RequestJump 接按下事件；恢复时额外保存垂直速度；平台、碰顶、空中恢复通过，见 [跳跃教程](跳跃重力与地面检测.md) |
| 诊断与弱网 | 网络根增加 NetworkDiagnostics，按需添加 WeakNetworkSimulator / NetworkDiagnosticsPanel | 连接前安装模拟器；开发构建测试；不与其他 UTP Driver 构造器争用，见 [诊断教程](网络诊断与弱网测试.md) |

模块独立不等于所有保障自动存在：Prediction 不引用 Security，但会调用核心验证契约；没有验证器时不会自动得到 Gate 的限流。Recovery 不自动知道背包、任务、生命或角色速度，业务需要提供快照。默认预测几何不会扫描场景里任意 Collider。

## 3. 连接前逐项核对

1. 所有参与者使用相同 ApplicationId、兼容协议、网络预制体及组件顺序；示例选相同 Tick 配置。自建项目用自己的 ApplicationId。
2. 网络根只保留一套；大厅场景不要再次放一套 NetworkManager。生命周期通过 MultiplayerSession 管理，不从另一脚本直接 StartHost/Shutdown。
3. 检查服务器出生点合法、不与静态箱体重叠；启用重力时角色中心 Y 至少为 FloorHeight + HalfHeight。
4. 使用恢复与预测时，RecoverablePlayer 先于 PredictedMovement 完成 PostSpawn；对新对象重新绑定业务引用，不继续持有旧 NetworkObjectId。
5. 模块及自定义请求规则在连接前安装。账号启用时确认主体含所需权限；预测内置操作使用 `play`。
6. 客户端窗口有焦点，输入框未抢占键盘；仅新 Input System 的项目将自己的事件接到 SetInput / RequestJump，也可先用示例屏幕按钮。

## 4. 从同机到跨平台，逐层验收

| 层次 | 实际操作 | 通过标准 / 尚不能证明的事 |
| --- | --- | --- |
| 同机两个窗口 | 运行 Start-LobbyAcceptance，准备、开始、移动、跳跃、返回大厅 | 检查状态和展示；同机通过不能证明局域网防火墙或跨地域链路可用 |
| 两台 Windows | 复制整个同版 LobbyWindows 目录；A 创建主机，B 填 A 的局域网 IP | 不填 127.0.0.1；两端状态变化、弱网恢复和重新加入均通过 |
| Linux 专用服务器 | 部署获准后，按 Linux 教程先前台启动，再用同版基础 Windows 程序加入 | 当前包只有基础场景，不能拿大厅 exe 直接与它验收大厅；本轮未部署/运行 |
| 跨地域 Relay | 两地设备使用各自身份，同一 WSS/DTLS 配置，通过加入码连接 | 记录地区、实际 RTT、断线原因和恢复结果；同机假后端测试不能代替真实云服务 |
| Android / iOS | 真机前台联机，再测试切后台、回前台、Wi-Fi 切换和系统结束进程 | 分开记录可恢复断线与进程被杀；有内存凭证不等于能跨进程恢复 |
| WebGL | 构建浏览器客户端，与选择 WSS 的其他参与者联调 | 不使用 UDP 直连；另验字体、输入、网页暂停和后端适配 |
| 容量与长时运行 | 在目标机器上逐步增加真实客户端，记录帧率、CPU、内存、带宽和失败率 | 参数接受 128 人不代表承载已验证；此项目尚无容量结论 |

两台 Windows 首次验收：A、B 都关闭旧实例；在 A 运行 LobbyDemo.exe 并创建局域网主机，在 B 运行同目录程序，填 A 的 IPv4 和相同 UDP 端口并加入。通过系统网络设置或 `ipconfig` 查看 A 的局域网地址。只处理实际阻挡该应用/端口的防火墙规则，不必关闭整机防火墙。两端都准备后开始游戏，重复跳跃教程的验收表，最后分别导出报告。

## 5. 自动测试怎么选

以下 PowerShell 命令在完整仓库根目录运行。需要 Unity 构建/测试的步骤先关闭占用本项目的编辑器；使用已有 exe 的进程测试不要求关闭其他 Unity 项目。基础程序和大厅程序须先按当前源码构建。

| 命令 | 覆盖内容 | 主要结果位置 |
| --- | --- | --- |
| `.\scripts\Verify.ps1` | EditMode、PlayMode、基础 Windows 构建和基础进程联机 | TestResults/editmode.xml、playmode.xml、smoke.json |
| `.\scripts\JumpTest.ps1` | 正常/中度/关闭预测：跳跃、平台、顶板、断网重力和空中恢复 | TestResults/Jump/summary.json |
| `.\scripts\PredictionTest.ps1` | 移动预测、校正重放、重新定基、配置不一致 | TestResults/Prediction/summary.json |
| `.\scripts\RecoveryTest.ps1 -DevelopmentAccounts` | 开启开发账号的七组恢复/取消/过期等检查 | TestResults/Recovery/summary.json |
| `.\scripts\SecurityTest.ps1` | 开发鉴权拒绝与业务请求检查 | TestResults/Security/summary.json |
| `.\scripts\LobbyTest.ps1` | 大厅权限、场景往返、锁房、移出 | TestResults/lobby.json |
| `.\scripts\WeakNetworkTest.ps1 -Profile Moderate` | 真实状态同步、诊断、短断网恢复和全丢包超时 | TestResults/WeakNetwork/summary.json |
| `.\scripts\PredictionComparisonTest.ps1` | 同协议 On/Off 软件起步响应对比 | TestResults/PredictionComparison/summary.json |

Verify 不会自动运行表中全部专项，也不会替你生成大厅构建。先运行 Tools → Han Multiplayer → Build Windows Lobby Demo，再进行涉及大厅的测试。各脚本有自己的探针与自动退出流程，不要将多个探针参数塞给同一个进程。报告通常覆盖同名结果；需要版本对比时先复制本轮报告和日志到独立目录。

## 6. 记录验收，定位失败

每一项记录“通过 / 失败 / 未测试”，不要用没有红色报错代替行为验收。失败时至少保留：

```text
包版本 / 自己游戏协议 / 程序构建时间：
设备、系统、Unity 版本、Host 或 Client：
连接方式：同机 / LAN / 独立服务器 / Relay
移动模式 On / Off / Legacy；Tick；弱网配置在哪一端：
重现步骤、预期结果、实际结果：
发生时的会话状态、恢复状态、错误代码：
两端日志目录和 JSON 报告路径：
```

房间码、恢复凭证、账号票据和后端密钥不要粘入公开反馈。源码中没有对应功能时标记为“未实现”，有实现但没上目标设备时标记为“未验证”。当前已知边界：无房间搜索/匹配、主机迁移、服务器重启存档恢复、坡面/台阶/移动平台、动态物理回滚或射击命中回溯；真实账号后台另行提供。平台和现有测试证据见 [兼容性](兼容性与架构.md) 与 [验证记录](验证记录.md)。
