# 网络诊断面板与弱网测试

本工具面向联调、测试和开发构建，可用于任何玩法，不要求 FPS 模块。默认不注入故障，不会修改系统网络、防火墙或远端服务器。

## 1. 在现有示例中使用

1. 用 Unity 6000.3.26f1 打开项目，等待编译完成。
2. 打开 `Assets/MultiplayerDemo/MultiplayerDemo.unity`，点击 Play。
3. 示例会自动安装诊断采集器、弱网模拟器和可拖动面板；旧示例场景也会在启动时安装，不需要删除重建。
4. 先用 创建局域网主机 + 另一个 Windows 程序 通过 IP 加入 建立连接。
5. 在诊断窗口观察 RTT、流量、状态和错误。**只运行一个 Host 没有远端链路，RTT 显示 N/A 属于正常情况。**
6. 在客户端选择「轻度 / 中度 / 严重」立即施加故障，或填写四个参数后点击「应用自定义参数」。房主先保持「正常」，便于比较单端注入效果。
7. 点击 模拟断网 3 秒 模拟短时双向断网；三秒后自动恢复之前的弱网配置。
8. 恢复正常网络 清除后续故障注入；导出本机 JSON 报告 导出本机报告并在日志显示路径。

默认只在 Editor 和 Development Build 显示面板、启用弱网；正式非开发构建禁止故障注入。Linux 正式服务端不会因为安装示例组件而自动施加弱网。关闭面板只影响显示；要恢复网络请点击「恢复正常网络」，或禁用 WeakNetworkSimulator 组件。大厅面板默认不展开诊断，需要点击「显示网络诊断」。

## 2. 面板数据如何理解

| 字段 | 含义与限制 |
| --- | --- |
| State / protocol | 本地会话状态，以及 Direct UDP / Relay DTLS / Relay WSS |
| Remote peers | 服务器已连接的远端数量；客户端只显示服务器，不代表完整大厅名单 |
| Peer RTT | UTP 可靠管线估计的往返时间，单位毫秒；不是单向延迟，也不是额外 Ping 包 |
| RTT N/A | 没有远端、还没有可靠管线估计，或驱动尚未建立；不能当作 0 ms |
| RX / TX kbit/s | Driver 最近一秒的聚合接收/发送速率；不是每名玩家单独流量 |
| Bytes / Packets RX/TX | 当前 Driver 生命周期内的累计字节/数据包数量；重连创建新 Driver 后重新计数 |
| Traffic | UTP 网络层统计，包含其可估计的协议开销；不是精确的操作系统抓包计费数值 |
| Measured packet loss | 当前不提供真实端到端丢包率估计，显示 N/A |
| Applied / drop % | 人为配置的故障注入值，**不是实际观测丢包率** |
| State events | 最近最多 20 条状态转换和错误，包含 UTC 时间 |

每 0.5 秒采集一次，最多保留最近 120 条，约一分钟。报告保留最近历史，离线后当前统计清零，但已有在线样本仍可导出。报告不主动采集房间码、认证 Token、Relay 密钥或游戏载荷；游戏自行写入错误信息的内容仍需由游戏开发者负责。

默认报告位于 `Application.persistentDataPath/NetworkReports`；Windows 通常是用户的 `AppData/LocalLow/公司名/产品名/NetworkReports`。按钮会在 Console 打印准确位置。文件名带时间和随机后缀，减少多实例覆盖。

## 3. 弱网参数及预设

| 预设 | 发送延迟 | UTP 发送抖动 | 发送丢包 | 接收丢包 |
| --- | --- | --- | --- | --- |
| Normal / None | 0 ms | 0 ms | 0% | 0% |
| Light | 40 ms | 10 ms | 1% | 1% |
| Medium / Moderate | 100 ms | 30 ms | 3% | 3% |
| Severe | 250 ms | 80 ms | 10% | 10% |

这些是测试组合，不代表某家运营商或地区的真实测量值。自定义延迟/抖动范围为 0～2000 ms，发送/接收丢包分别为 0～100%。非法值和 NaN/Infinity 会被拒绝，不会静默替换成正常网络。

- **发送延迟只作用于当前进程发出的数据。** 只给客户端加 100 ms 延迟，不意味着 RTT 恰好增加 200 ms；需要考虑实际作用的方向、抖动和重传。
- 抖动采用 UTP 2.7 的全局模拟层实现，不要按严格的 `延迟 ± 抖动` 对称分布理解。
- 发送和接收丢包独立抽样；两个设备都启用后，链路会叠加多次故障注入，不是简单取其中一个百分比。
- 模拟层作用于该 Driver 的全部数据，包括连接控制数据，因此建连也可能变慢或超时。它不模拟 Authentication / Relay 分配等 HTTP 请求，也不影响机器上其他应用。
- Reliable 消息丢包后可能重传；配置 10% 丢包不等于 10% 的业务 RPC 永久消失。
- 3 秒结束只恢复故障注入前的网络参数。若尚未达到 UTP 断开超时，通常继续原连接；若已经超时断开，弱网工具自身不负责重连。当前示例默认另装 `RecoveryService`，会在凭证有效且预算允许时自动重连；未安装恢复模块的项目需要主动重新加入。被踢出、主动退出和凭证过期不会自动恢复。
- 「恢复正常网络」/ 禁用工具会停止继续注入故障，已经延迟排队的数据仍可能随后到达；连接恢复也需要正常的网络处理时间。
- 可以暂停游戏后测试断网恢复：定时器使用真实时间，不随 Time.timeScale 暂停。

## 4. 在自己的场景中安装

在已有 NetworkManager、UnityTransport、MultiplayerSession 的同一个根对象上，添加：

1. `NetworkDiagnostics`：采集数据，可单独使用；UTP RTT/流量采集不发送额外探测包。旧版移动的响应测量会请求额外回执；预测模式复用必要的权威状态通知。关闭响应采集不关闭预测同步，具体区别见 [时序与测量](同步时序与延迟优化.md)。
2. `WeakNetworkSimulator`：可选的故障注入组件，**在开始连接前启用**。
3. `NetworkDiagnosticsPanel`：可选 IMGUI 界面；添加时会要求前两项组件。

使用 asmdef 的脚本引用 `Han.Multiplayer.Diagnostics`，核心 `Han.Multiplayer` 不引用这个工具程序集。场景中途安装弱网工具时，当前 Driver 没有模拟层，需要断开再连接一次。

工具使用 UTP 2.7 的公共 Driver 构造入口安装全局模拟层，保留默认网络设置及可靠/不可靠管线。没有安装工具的 Transport 走默认构造。**不要与另一个已经占用 `UnityTransport.s_DriverConstructor` 的网络模拟工具同时使用**；发生冲突时本工具会警告并拒绝应用，不会覆盖其他工具的构造器。最后一个本工具组件关闭后释放自己的入口。

Inspector 配置用于启动；运行时修改 Inspector 数值不会自动提交给 Driver，使用面板 Apply 或调用 `Apply(settings)`。仅隐藏面板不停止采集和模拟。

## 5. 命令行操作示例

以下参数由 DemoLauncher 解析，自己的启动器需要自行调用 `WeakNetworkSimulator.ConfigureFromArguments(args)` 或 API。先重新构建 Windows Demo，旧程序不包含这些功能。

在项目根目录的一个 PowerShell 中启动正常主机：

```powershell
& '.\Builds\Windows\MultiplayerDemo.exe' --net-mode host --net-port 7777
```

在另一个 PowerShell 中启动中等弱网客户端：

```powershell
& '.\Builds\Windows\MultiplayerDemo.exe' --net-mode client --net-address 127.0.0.1 --net-port 7777 --net-sim Moderate
```

自定义发送延迟、抖动和双向丢包：

```powershell
& '.\Builds\Windows\MultiplayerDemo.exe' --net-mode client --net-address 127.0.0.1 --net-port 7777 --net-sim Custom --net-delay 120 --net-jitter 30 --net-send-loss 3 --net-receive-loss 2
```

预设参数按命令行顺序处理，先写 `--net-sim`，再写覆盖它的自定义参数。`--net-no-panel` 隐藏开发面板；这不关闭采集或弱网。

## 6. 一键运行真实多进程测试

退出占用项目的编辑器后，可以先运行 `scripts/Verify.ps1` 重建 Windows 示例并验证原有场景；已有新构建时直接执行：

```powershell
.\scripts\WeakNetworkTest.ps1
```

只测中等弱网：

```powershell
.\scripts\WeakNetworkTest.ps1 -Profile Moderate
```

每组启动正常 Host、弱网 Client，再启动双向 100% 丢包的 Client。验证项目包括：

1. 两端实际观察到远端生成、移动和 准备 同步。
2. 诊断报告有真实在线 Driver、远端和非零收发流量。
3. 弱网客户端测得的 RTT 确实体现注入的发送延迟。
4. 在线六秒后短时断网三秒，再重新观察远端移动，不能仅凭断网前的成功证据通过。
5. 双向 100% 丢包客户端不能完成建连，并按会话期限报超时。

日志位于 `Logs/WeakNetwork`，每端报告和汇总位于 `TestResults/WeakNetwork`。脚本只结束自己创建的进程。此工具不属于 Linux 部署步骤，不连接或修改 `192.168.1.111`。

## 7. 已知测试边界

本工具不是带宽限速器，没有模拟蜂窝切换、DNS 故障、HTTP 云服务延迟或完整路由行为。全局模拟层在不同传输协议上注入的数据单位不完全等价，尤其 WSS 不应被理解为精确模拟互联网底层 TCP 的物理丢包过程。Relay、WebGL 和各移动设备仍需实际联调。

UTP 官方接口说明：[NetworkSimulatorParameter](https://docs.unity3d.com/Packages/com.unity.transport@2.7/api/Unity.Networking.Transport.NetworkSimulatorParameter.html)。


## 输入与同步时序

当前支持实际 FPS、输入发送 Hz、服务器模拟 Hz、输入确认耗时及静止起步位置响应，见 [同步时序与延迟优化](同步时序与延迟优化.md)。旧版移动的开发回执可以关闭；预测模式的必要权威状态仍正常发送。RTT/流量采集读取 UTP 统计。
