# 可插拔账号准入与统一请求校验（0.6.0）

当前示例为 0.8.0、协议 6，需重建两端。新增可选 [跳跃、重力与地面检测](跳跃重力与地面检测.md)，包括垂直状态校正与空中恢复；下文带旧版本号的段落保留其历史说明。

本模块提供账号验证的接入点、HTTPS 后端适配器、服务器账号绑定，以及请求权限/参数/阶段/限流/序号检查。它不依赖 FPS，也不附带真实账号数据库、注册登录网页或平台账号 SDK。

`Han.Multiplayer.Security` 是独立程序集。客户端只提交登录票据，服务器取得验证后的 AccountId、权限和有效期；昵称和客户端自报的角色不能成为授权依据。恢复连接需要重新验证票据，且账号必须与原角色绑定一致。

## 1. 先在两个窗口验收

重新构建基础和大厅 Windows 示例后，在项目目录 PowerShell 运行：

```powershell
.\scripts\Start-LobbyAcceptance.ps1 -DevelopmentAccounts
```

1. 左侧应显示「开发模拟（非真实登录）」及服务器确认后的账号：房主 `host`、玩家 `guest`。
2. 正常测试昵称、准备、开始、返回和移动。昵称可以使用中文，账号 ID 使用独立的机器标识。
3. 在第三个大厅程序窗口选择开发鉴权，账号 ID 填 `guest` 后连接，已在线的同账号应被拒绝。不要只修改昵称来测试重复登录。
4. 两端开始游戏。在客户端点击「模拟连接中断（测试重连）」，恢复后仍是 `guest` 账号和原逻辑角色。
5. 在房主窗口查看允许/拒绝请求计数。被移除的一端不能通过自动重连规避踢出；开发模拟不会创建永久账号封禁。

不加开关时，示例仍默认使用无账号的局域网模式，但启用请求校验。开发构建也可以在连接前勾选「启用开发账号验收」。正式构建强制禁止开发验证器，不能用它代替生产登录。

开发验证器允许自行选择测试账号，只用于验证接入流程。`banned`、`slow`、`late` 为自动测试保留账号，分别模拟禁止进入、慢后端和忽略取消的迟到结果。

## 2. 模块与接入顺序

```text
客户端登录 SDK / 你的登录 UI
  → IClientCredentialProvider（获取短票据）
  → 核心有界握手（游戏/版本 + 账号票据 + 可选恢复凭证）
  → IAccountTokenValidator（服务器验证）
  → AccountAdmissionService（重复登录与账号绑定）
  → Recovery / Lobby / 容量等规则
  → ServerRequestGate（每次业务请求再次校验）
```

核心通过 `IConnectionAuthenticator` 和 `IServerRequestValidator` 契约连接可选模块，不引用 Security 程序集。已有的 `IConnectionAdmissionRule` 仍可进一步拒绝连接，不能绕过账号、版本和容量检查。

NGO 会自动批准 Host，本模块先完成 Host 的账号验证再开启监听；远端使用有超时的异步 Pending。默认最多同时验证 16 个远端请求、每次 5 秒，客户端原有的总连接超时也仍生效。断开或关闭后，迟到结果不能写入身份表或生成玩家。

## 3. 安装到自己的项目

### 3.1 网络根对象

在 NetworkManager 所在对象上添加 `AccountAdmissionService`。它会要求 `MultiplayerSession` 和 `ServerRequestGate`。在连接前配置两个字段：

- Credential Provider：实现 `IClientCredentialProvider` 的 MonoBehaviour；负责从你的登录流程取得票据。
- Token Validator：实现 `IAccountTokenValidator` 的 MonoBehaviour；在服务器/Host 上验证票据。

纯客户端可以不配置 Token Validator；独立服务器可以不配置本地 Credential Provider。Host 同时需要两者。全部配置应在连接前完成，不应在线更换插件。

自定义 asmdef 引用 `Han.Multiplayer`、`Han.Multiplayer.Security`；直接使用 NGO 类型时另加 `Unity.Netcode.Runtime`。恢复模块仍独立安装，不因开启账号就自动保存任意角色状态。

### 3.2 最简单的客户端接入

`MemoryCredentialProvider` 不序列化票据。你的登录流程成功后，将后端返回的短票据交给它：

```csharp
using System.Threading.Tasks;
using Han.Multiplayer;
using Han.Multiplayer.Security;
using UnityEngine;

public sealed class AccountConnector : MonoBehaviour
{
    public MultiplayerSession Session;
    MemoryCredentialProvider credentials;

    void Awake()
    {
        credentials = Session.GetComponent<MemoryCredentialProvider>()
            ?? Session.gameObject.AddComponent<MemoryCredentialProvider>();
        var accounts = Session.GetComponent<AccountAdmissionService>()
            ?? Session.gameObject.AddComponent<AccountAdmissionService>();
        // 这是纯客户端；验证器在服务器配置，不在这里自行声称“验证成功”。
        accounts.SetProviders(credentials, null);
    }

    public async Task JoinAsync(string shortTicket, string address, ushort port)
    {
        credentials.SetCredential(shortTicket); // 来自你自己的登录结果。
        await Session.JoinDirectAsync(address, port);
    }

    public async Task LogoutAsync()
    {
        await Session.StopAsync();
        credentials.ClearCredential();
    }
}
```

保存为 `AccountConnector.cs`，挂到自己的 UI/引导对象并指定 Session。自己的场景不需要 DemoLauncher；若保留示例启动器，它会保留已经配置好的账号组件，或可显式使用 `--net-auth configured`。

票据最多 **256 个 UTF-8 字节**，整个连接封包仍最多 512 字节。较大的 JWT/平台 Access Token 应先向自己的登录后端交换短连接票据，不能直接假定任意 SDK Token 都能塞进握手。

### 3.3 自定义登录 SDK 或后端验证

客户端接口每次初始连接及重连都会调用，可以在实现中获取/刷新短票据：

```csharp
Task<string> GetCredentialAsync(CancellationToken cancellationToken);
```

服务器接口如下：

```csharp
Task<AccountValidationResult> ValidateAsync(
    string credential, string applicationId, CancellationToken cancellationToken);
```

成功返回 `AccountValidationResult.Accept(new AccountPrincipal(...))`；失败返回 `Reject("AUTH_INVALID_TOKEN")` 等错误码。验证结果必须来自可信后端或真正的签名验证，不能只解析客户端 JSON/JWT 字段后直接 Accept。

AccountId 和 ApplicationId 最多 64 个 ASCII 字符，允许字母、数字、点、下划线、连字符，比较区分大小写。平台 ID 应在后端规范化为稳定标识。权限最多 32 项，精确匹配，默认无通配权限；例如 `play`、`lobby.use`、`inventory.trade`。不得将客户端传来的 `admin=true` 原样转换为权限。

验证器应遵守取消令牌。框架即使遇到不合作的实现，也会停止等待超时结果；内置服务在取消后会再次检查，防止迟到身份复活。自定义插件不应抛出含票据、密钥或响应正文的异常，也不应自行把凭证写入日志。

## 4. HTTPS 账号后端适配器

服务器添加 `HttpAccountTokenValidator` 并配置 Endpoint。默认要求 HTTPS、使用系统证书校验，不跟随重定向，也不跨账号保存或发送后端 Cookie。服务器密钥从 `ServerKeyEnvironmentVariable` 指定的环境变量读取，默认名称是 `HAN_ACCOUNT_BACKEND_KEY`；场景只保存变量名。若后端采用其他服务间认证，可以替换验证器；只有后端明确无需此头时才把变量名留空。

适配器发送：

```http
POST /game/validate
Content-Type: application/json; charset=utf-8
X-Game-Server-Key: <由服务器环境注入，不放入客户端>

{"token":"<客户端短票据>","applicationId":"my-game"}
```

后端成功返回 HTTP 2xx、Content-Type `application/json`：

```json
{
  "valid": true,
  "accountId": "player.123",
  "applicationId": "my-game",
  "expiresUnixSeconds": 2000000000,
  "permissions": ["play", "lobby.use"]
}
```

`expiresUnixSeconds` 是后端签发的真实 UTC 过期时间，示例数字不能照抄进生产。后端必须真正验证票据签名/数据库状态、应用归属、过期和封禁，再生成这些字段。拒绝示例：`{"valid":false,"error":"AUTH_INVALID_TOKEN"}`。响应最多 8 KiB；缺失或非法主体、错误应用、过期、不正确内容类型和超大响应均拒绝。

HTTP 5xx、408、429 和连接故障作为暂时不可用；重连可在原预算内重试。其他非成功响应拒绝验证。错误不回显后端正文。自动测试的 HTTP 回环例外只在显式开启且为开发环境时有效，不能用于生产。

示例启动器也支持 `--net-auth http`：服务器地址由 `HAN_ACCOUNT_BACKEND_URL` 提供，服务器密钥由 `HAN_ACCOUNT_BACKEND_KEY` 提供，客户端短票据由 `HAN_ACCOUNT_TOKEN` 提供。不要把密钥或票据加入命令行、版本库或诊断报告。真实登录 UI、密钥注入与账号后端需要项目自己提供；本轮没有部署这些外部服务。

## 5. 重复登录、踢出、封禁和过期

- 默认拒绝同一房间中的重复账号，不会自动把在线玩家挤下线。
- 离线席位保留时，只有同账号且持有原恢复凭证才能恢复；只有账号、昵称或只有恢复凭证都不够。
- 重新连接后 NGO ClientId 会改变，账号 ID 和逻辑恢复身份用于业务关联。
- 主动退出或 `session.DisconnectPlayer(id, reason)` 默认撤销恢复资格；临时故障才使用 `allowRecovery:true`。
- 服务器可调用 `accounts.BanAccount(accountId)`，撤销在线/保留中的连接并拒绝本次服务器会话内再入。持久封禁应由账号后端保存；仅踢出不等于永久封禁。
- 当前实现会在已验证凭证过期时撤销连接和恢复资格；Host 凭证过期会结束其房间。重连期间每次重新获取票据，但**尚未提供在线续签协议或完整登录界面**。后端应按游戏会话选择有效期，或在项目层补充重新登录/续签流程。

普通直连 UDP 仍未自动加密。HTTPS 保护的是游戏服务器到账号后端这段通信，不会把客户端到游戏服务器的 UDP 自动变成安全传输；不可信网络中的正式账号票据应通过受保护的游戏传输，例如合适配置的 Relay DTLS/WSS。账号准入也不等于反作弊或防御所有网络洪泛。

## 6. 统一请求校验

示例已接入移动、玩家准备、大厅昵称/准备/规则/开始/返回/踢人及恢复离场。它不能自动拦截你新写的所有 RPC；每个客户端到服务器的业务入口都必须显式接入。

### 不启用账号，也要显式安装请求验证器

1. 在 NetworkManager / MultiplayerSession 的同一根对象上添加 `ServerRequestGate`，连接前安装并启用；匿名 LAN 项目无需为了限流额外安装 `AccountAdmissionService`。
2. 自己的 asmdef 若直接使用 Gate 类型，添加 `Han.Multiplayer.Security` 引用；调用核心请求契约时引用 `Han.Multiplayer`。
3. Gate 自动注册框架内置规则，包括预测输入和重新定基。自定义业务规则在连接前注册，服务器 RPC 入口调用 `session.ValidateRequest(...)`，返回非 null 时结束操作。
4. 启用账号后，预测移动使用 `play` 权限；后端返回的主体缺少它时，请求会被拒绝。不要把“登录成功”当作“所有操作均获准”。

自带 DemoLauncher 会自动添加 Gate，自己的启动器不会。若没有 Gate 或其他 `IServerRequestValidator`，核心只做基础连接、参数、所有权、阶段检查，不执行统一频率预算；启用账号却缺少验证器时会拒绝请求。输入窗口去重、每 Tick 一步和 Gate 限流是三项不同约束。

### 注册规则与调用入口

在服务器启动前注册固定、不可变规则：

```csharp
// 放在业务类静态字段中，不从客户端的请求内容创建规则。
static readonly ServerRequestRule TradeRule = new ServerRequestRule(
    "inventory.trade", rate: 2, burst: 2, maximumBytes: 64,
    ownership: true, sequence: true, permission: "inventory.trade", requireAccount: true);

// 网络根对象的初始化阶段，建立连接之前：
gate.RegisterRule(TradeRule);
```

服务器收到 RPC 后：

```csharp
// sender 必须取 rpc.Receive.SenderClientId，不能取客户端传来的“我的账号/所有者”。
// owner、validPayload、phaseAllowed、sequenceScope 均由服务器读取或计算。
string error = session.ValidateRequest(TradeRule, rpc.Receive.SenderClientId,
    trustedObject.OwnerClientId, payloadBytes,
    validPayload: serverValidatedItemAndAmount,
    phaseAllowed: serverAllowsTrading,
    sequence: commandSequence,
    sequenceScope: trustedObject.NetworkObjectId);
if (error != null) return;
// 继续验证余额、物品归属、距离等具体业务，再执行交易。
```

示例中的规则是 2 次/秒、突发 2 次，权限精确匹配；同时检查真实连接、确认后的身份和过期、请求大小/参数、所有权及阶段。要求序号的操作拒绝重复和旧序号，处理 uint 回绕，并按服务器对象隔离序号，避免重生后合法新命令被旧序号阻挡。

默认还有每个连接 240 次/秒、突发 240 次的合计预算。无效/越权请求也消耗预算，切换操作不能绕过合计限制。最多 64 种规则、128 个连接，每连接最多 128 组操作/序号作用域；断开后清理状态；示例还在玩家对象移除时释放其序号作用域，防止多次重生耗尽作用域或复用旧序号。自己的序号对象也应在服务器销毁时调用 `session.ForgetRequestScope(ownerClientId, objectId)`，此操作不会重置连接总预算。规则应按玩法调整源码或替换校验实现，不能假定这些默认值适用于所有游戏负载。

没有安装账号组件的 LAN 项目仍可使用请求限流/所有权检查；需要强制账号的操作设置 `requireAccount:true`。启用账号组件后，所有接入 Gate 的请求都要求服务器已确认身份；权限从主体读取。大厅房主权限、人数、准备、库存余额等业务规则仍在对应服务器逻辑中检查，不能只靠隐藏按钮。

自动 RPC 参数已经在进入方法前反序列化；对可变长度大载荷，应在读取前使用有界格式/读取器，不能把事后大小检查当作完整的反序列化防护。自定义 NamedMessage 的应用大小应在读取前取 `reader.Length - reader.Position`。

## 7. 自动验证与平台边界

```powershell
.\scripts\Verify.ps1
.\scripts\SecurityTest.ps1
.\scripts\RecoveryTest.ps1 -DevelopmentAccounts
```

SecurityTest 启动真实 Host/客户端，验证无凭证、伪造、过期、封禁、重复账号、验证超时及迟到结果不创建角色；通过真实消息验证权限、所有权、NaN、阶段、载荷边界、序号重放和限流。恢复测试增加账号不匹配拒绝。汇总在 `TestResults/Security/summary.json`、`TestResults/Recovery/summary.json`，日志在对应 Logs 子目录。

Unity PlayMode 还用回环假后端测试真实 HTTP 请求、服务器密钥头、应用校验、响应上限、缺少密钥和暂时故障。没有访问真实生产账号后端，不能将这些结果等同于已接入你的登录服务。

本轮示例协议升为 **4**，重新构建双方程序。框架包为 0.6.0，核心握手的账号扩展与旧恢复扩展区分编码，旧读取器不能静默忽略账号段。Windows 为主要运行验证平台；Linux 为本地专用服务器编译/打包验证，未上传或运行。HTTPS 适配器使用 System.Net.Http，目标平台、证书库和网络环境需实机验证；WebGL Host 等环境可按接口替换为适用的实现。

设计参考：[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)中的默认拒绝、逐次授权和测试原则；后端适配遵循 [OWASP REST 安全指南](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)对 HTTPS、输入约束和错误信息的建议。本模块实现不等于第三方安全审计认证。
