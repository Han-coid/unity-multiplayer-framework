# 跳跃、重力与地面检测（0.8.0）

本轮扩展现有 `Han.Multiplayer.Prediction`，仍不依赖 FPS、大厅、账号或恢复程序集。示例启用跳跃，自己项目的 `MovementSettings.EnableVertical` 默认关闭，可继续只使用水平移动。核心连接层不强制使用该角色控制器。

## 1. 两个窗口人工验收

先关闭上次验收的两个游戏窗口，在项目目录 PowerShell 运行：

```powershell
Set-Location 'D:\Unity 通用联机框架' # 若项目放在其他目录，改为实际路径。
.\scripts\Start-LobbyAcceptance.ps1
# 仅在 7777 已占用时改用：.\scripts\Start-LobbyAcceptance.ps1 -Port 7788
```

两个窗口会自动连接本机；两端点击“准备”，再由房主点击“开始游戏”。重点操作昵称“玩家”的客户端，先点击画面空白处获得键盘焦点，再使用 WASD 移动、空格跳跃，也可点击左下角“跳跃（按一次）”。确认移动模式为“本地预测 + 服务器校正”，不要选择“旧版移动”。按住空格不会自动连跳；空中再按一次不会缓存到落地后。

脚本需要完整源码仓库中的 `scripts` 和已构建的 `Builds/LobbyWindows`；只把 UPM 包导入新项目不会带入这些目录。缺少 exe 时，在原示例项目使用 Tools → Han Multiplayer → Build Windows Lobby Demo。实际运行日志在脚本打印的 `Logs/LobbyAcceptance/时间戳` 下。

| 项目 | 操作 | 预期 |
| --- | --- | --- |
| 平地跳跃 | 站在空地按空格，然后不再按键 | 起跳、到达最高点、下降并落地；落地后垂直速度为 0 |
| 不重复起跳 | 按住空格；另外尝试在上升时再按一次 | 单次按下只分配一条输入；不获得二段跳，不在落地后自动起跳 |
| 低平台 | 走向世界坐标 X=4、Z=-4 的矮箱；再起跳并向箱上移动 | 直接走被侧面挡住；跳上后站在平台顶面，走出边缘会下落 |
| 顶板 | 到 X=-4、Z=4 的悬空箱下跳跃 | 头顶碰到箱底后停止上升并落下，不穿顶板 |
| 弱网跳跃 | 仅客户端在诊断面板选择“中度”，重复起跳、移动和落地 | 本地及时响应，服务器仍决定真实状态；可发生校正，但恢复正常网络后不应持续抖动 |
| 空中断网 | 跳起后点“模拟断网 3 秒（自动恢复）”，期间松开所有输入 | 服务器继续重力，不因无输入悬停；恢复后清理旧输入，不自动补跳 |
| 重连 | 恢复正常网络后起跳，点击左侧“模拟连接中断（测试重连）” | 原角色快照位置与垂直速度恢复，继续落地；不重放旧对象的待执行跳跃 |

客户端显示的“已落地 / 空中”和垂直速度来自本地模拟，网络异常时可能暂时与服务器不同；权威包到达后会重算。Host 显示服务器状态。旧版移动不支持跳跃。

空中点击中断按钮的时间很短，可先将鼠标放到按钮上，再按空格并立即点击。若点击时已经落地，只能算普通重连通过，不能算空中恢复通过；`JumpTest.ps1` 会使用较高的受控出生位置，自动验证非零下落速度的恢复。每次弱网测试结束先点“恢复正常网络”，再进行下一项。至少重复 3 次跳跃/落地，记录是否有穿透、重复角色、持续抖动或恢复后自动补跳。

关闭两个窗口，再运行 `./scripts/Start-LobbyAcceptance.ps1 -PredictionMode Off` 可对比关闭本地展示预测时的跳跃延迟。On/Off 使用相同服务器运动协议。

## 2. 运动模型与适用范围

- 角色是轴对齐箱体，`Position` 是中心；宽度为 `HalfWidth × 2`，高度为 `HalfHeight × 2`，不从 Transform 缩放或 Collider 自动读取。
- 水平运动沿 X、Z 顺序扫掠；随后进行垂直扫掠。使用固定 Tick 的共享算法，不调用 Rigidbody 积分。
- `FloorHeight` 是覆盖整个世界水平范围的平面地面高度。箱体障碍可以充当墙、平台和天花板。
- 支撑由脚底与地面 / 箱体顶面的接触重新判定。离开平台边缘就开始下落；不提供土狼时间、提前跳跃缓存或自动跨台阶。
- 不包含坡面、任意 MeshCollider、玩家之间碰撞、动态障碍、移动平台、蹲伏或射击命中回溯。

这是一套基础可预测控制器，不会自动接管已有 Unity CharacterController、Rigidbody 或第三方角色插件。同一根对象不能同时被两套运动逻辑驱动。

## 3. 在自己的项目启用

先按 [基础预测接入](基础移动预测与服务器校正.md) 安装网络根、Gate、玩家组件和 VisualRoot。下列是配置片段，放入自己的连接准备方法，执行后再调用会话启动方法；`prediction` 指网络根上的 `MovementPredictionSession`，不是可直接单独保存为 .cs 的完整脚本：

```csharp
// 根对象上的配置；两端必须一致，启动时会冻结副本。
prediction.Settings.EnableVertical = true;
prediction.Settings.HalfWidth = 0.5f;
prediction.Settings.HalfHeight = 1f;
prediction.Settings.FloorHeight = 0f;
prediction.Settings.Gravity = 20f;       // 向下加速度，填写正数。
prediction.Settings.JumpSpeed = 7f;      // 初始向上速度。
prediction.Settings.TerminalSpeed = 30f; // 最大下落速度。
prediction.Settings.Obstacles = new[] {
    new MovementObstacle(new Vector2(4, -4), Vector2.one, 0f, 0.6f),
    new MovementObstacle(new Vector2(-4, 4), Vector2.one, 2.7f, 3f)
};
```

`MovementObstacle` 参数依次为 X/Z 中心、X/Z 半尺寸、底面 Y、顶面 Y。两端几何、速度、重力、角色尺寸和 Tick 都参与配置指纹；不匹配时停止运动。运行时不热修改该几何。

| 字段 | 默认值 / 单位 | 设置时检查 |
| --- | --- | --- |
| EnableVertical | 自建配置 false；Demo 显式设 true | 两端一致；关闭时不模拟重力和跳跃 |
| HalfWidth / HalfHeight | 0.5 / 1，世界单位 | 完整碰撞宽度 1、高度 2；不自动读取模型或 Collider |
| FloorHeight | 0，世界 Y | 地面视觉也放在对应高度；出生中心 Y 默认 1 |
| Gravity | 20，单位/秒² | 填正数，内部向下积分；范围大于 0 且不超过 200 |
| JumpSpeed | 7，单位/秒 | 初始向上速度；范围大于 0 且不超过 50 |
| TerminalSpeed | 30，单位/秒 | 下落速度绝对值上限；范围大于 0 且不超过 100 |
| Obstacles | 自建配置为空 | 最多 32 个，垂直开启时每个 Bottom 必须小于 Top |

静态几何数据与可见模型是两件事。箱体模型位置设为 `(Center.x, (Bottom + Top) / 2, Center.y)`，尺寸为 `(HalfSize.x * 2, Top - Bottom, HalfSize.y * 2)`。只在场景放一个 Cube 不会自动加入预测碰撞世界；只填 Obstacles 而不放模型会产生不可见障碍。

输入仍通过 `movement.SetInput(direction, MovementClock.Now)` 传递。将旧输入系统的 `Input.GetKeyDown(KeyCode.Space)`、新 Input System 的按钮按下事件或触屏点击接到 `movement.RequestJump()`。每次按下调用一次，不要在持续按住期间每帧调用。组件将事件保存到下一网络 Tick；重新定基、阶段禁止、失去所有权和新对象初始化时清理待执行事件。

出生点应满足 `centerY = FloorHeight + HalfHeight`，且不能与箱体重叠。空中出生允许，但会开始下落。展示模型、相机和动画继续使用预测展示位置；不要用根 Transform 取代本地预测模型。

## 4. 校正、输入重放与无输入重力

`MovementState` 包含 `Position`、`VerticalVelocity`、`Grounded`。客户端每个历史输入都保存完整执行结果；服务器确认后从完整权威状态重放尚未确认输入。即使位置相同，只要速度或落地标记不同，也会修正；显示平滑只作用于位置，不延迟逻辑落地与速度恢复。

32 条输入窗口增加一个 32 位跳跃位图，固定序列化为 73 字节，加上输入代次和世界指纹，RPC 参数为 81 字节（不含 NGO/传输封装）。重复窗口按输入序号去重，不会重复执行同一跳跃。客户端不上传位置、速度或自定时间步长。

服务器每 Tick 至多消费一条输入。暂时无输入时水平意图和跳跃均为零，但重力仍按服务器 Tick 推进；不会伪造输入确认序号。客户端随后校正完整状态。大厅阶段等 `IMovementAuthorityPolicy` 禁止模拟时，整个角色模拟暂停。

```csharp
// 真正传送：清空速度与旧输入，从新位置重新判定支撑。
movement.TeleportOnServer(new Vector3(0, 5, 0));

// 同一代次的完整状态校正：例如服务器施加向下速度。
var corrected = prediction.World.CreateState(new Vector3(0, 5, 0), -3f);
movement.CorrectOnServer(corrected);
```

只传 `Vector3` 的 `CorrectOnServer` 保留现有垂直速度，并按目标位置重算支撑；需要清空速度时使用完整状态或传送。所有接口只允许服务器调用，非法位置、速度和落地标记会被拒绝。

## 5. 断线恢复接入

Prediction 不引用 Recovery。示例的 `DemoPlayer` 通过 `IPlayerRecoveryState` 保存准备状态与服务器垂直速度；恢复模块另存根位置。恢复时在 `PredictedMovement.OnNetworkPostSpawn` 初始化前调用 `PrepareRecoveryVelocityOnServer(savedVelocity)`，然后预测组件读取已经恢复的根位置并重新计算落地状态。

因此自己的恢复适配器也要保证恢复组件在预测组件之前完成 PostSpawn，并保存服务器的垂直速度。没有恢复适配时，新对象从零垂直速度开始。服务器保留的是断线时快照，不会在玩家离线期间持续模拟其重力；重新加入后从快照继续，不进行离线时长快进。

恢复快照不保存待执行跳跃、未确认历史或输入队列。示例快照键改为 `demo.player.v2`；跨版本旧会话不可恢复。

自己的角色没有使用 DemoPlayer 时，可将以下完整脚本保存为 `PredictedMovementRecovery.cs` 并挂到玩家根对象。不要再给已有 DemoPlayer 重复添加这份速度提供者；它已经做了相同工作。

```csharp
using System;
using Han.Multiplayer.Prediction;
using Han.Multiplayer.Recovery;
using Unity.Netcode;
using UnityEngine;

// 本脚本只提供运动速度快照，不处理网络启动或生成玩家。
[RequireComponent(typeof(PredictedMovement))]
public sealed class PredictedMovementRecovery : NetworkBehaviour, IPlayerRecoveryState
{
    public string RecoveryKey => "game.movement.v1";

    public byte[] CaptureRecoveryState()
    {
        if (!IsServer) throw new InvalidOperationException("Server snapshot only.");
        // 仅保存在同一服务器进程内；根位置由 RecoverablePlayer 保存。
        float velocity = GetComponent<PredictedMovement>().AuthoritativeState.VerticalVelocity;
        return BitConverter.GetBytes(velocity);
    }

    public void RestoreRecoveryState(byte[] data)
    {
        if (!IsServer || data == null || data.Length != 4)
            throw new ArgumentException("Invalid movement snapshot.");
        // RecoverablePlayer 必须排在 PredictedMovement 之前，后者尚未完成 PostSpawn 初始化。
        GetComponent<PredictedMovement>().PrepareRecoveryVelocityOnServer(BitConverter.ToSingle(data, 0));
    }
}
```

该脚本的 asmdef 需要引用 `Han.Multiplayer.Prediction`、`Han.Multiplayer.Recovery`、`Unity.Netcode.Runtime`。网络根添加 RecoveryService；玩家根的 NetworkBehaviour 顺序建议为业务出生组件 → RecoverablePlayer → PredictedMovement → 展示/快照适配。Inspector 组件菜单可 Move Up/Down；这是网络组件顺序，不是 Project Settings 中的脚本 Update 执行顺序。修改后保存预制体并重建双方。

若已有自己的恢复提供者，可以将垂直速度合并进它的快照，不必增加新组件；恢复键必须唯一，并在快照结构不兼容时更新键/协议。输入与碰撞仍由预测组件处理，适配器不能在每帧自行施加第二份重力。

## 6. 版本与验证边界

包版本 0.8.0，示例协议 6。请重建所有参与者；旧 0.7.0 可执行程序不能与本版混用。水平 API 保留兼容入口，但网络状态布局及运动世界指纹已更新。

自动测试：运行 `./scripts/JumpTest.ps1` 检查正常、中度弱网、关闭预测三组真实双进程流程；运行 `./scripts/PredictionTest.ps1` 检查原有移动预测。结果见 [验证记录](验证记录.md)。同机无图形测试不能替代图形手感、跨设备浮点表现或真实移动端 / WebGL / Relay 验收。Linux 构建只在本机完成，不会上传或部署服务器。
